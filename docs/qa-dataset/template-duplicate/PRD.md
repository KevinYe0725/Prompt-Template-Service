# PRD：将指定版本复制为新模板

- 版本：1.0；日期：2026-10-30（北京时间）
- 状态：本数据集任务的模拟产品规格；由 Codex 在用户授权其选题和设计的范围内编写，未声称独立产品负责人已审批。
- 基线：`10aeb958fe35c64b0b84388283d40e3ef64850cb`；适用于 Prompt Template Service。

## 背景与目标

当前详情页“复制为新版本”进入编辑器，再向同一名称追加版本；无法把某个已存在版本直接变成独立的新名称。模板维护者需要以可用版本为起点创建另一业务模板，又不希望复制过程影响正在使用的版本。

复制前，`interview:v2` 的 active 渲染读取原始版本；复制到 `interview-support` 后，原始模板及其 active 选择不变，新名称下仅新增未启用的 `v1`。用户可以先预览、编辑，确认后再主动启用新模板。

主要使用者：维护 prompt 的业务或技术人员；使用 active 名称渲染的下游调用方。目标是降低重复录入并隔离上线状态。非目标：复制整组版本或日志、批量复制、自动启用、模型调用、权限体系、改变现有“复制为新版本”的语义，以及对名称跨版本竞争引入新数据库表或锁。

## 业务要求与验收

| ID | 要求及可观察结果 |
| --- | --- |
| BR-01 | 详情页针对当前所选的具体版本提供“复制为新模板”，与现有“复制为新版本”并存。弹窗显示建议名称 `<来源名称>-copy`，用户可编辑；取消不发送创建请求、不改变数据。 |
| BR-02 | `POST /api/prompts/{template_id}/duplicate` 接收 JSON `{"name":"..."}`。去除名称首尾 Python `str.strip()` 空白后，名称按 Unicode 码点计 1–100 个字符；字段缺失、非字符串、空白或超长为 422。提交期间按钮和名称输入不可重复操作，返回错误保留弹窗并显示字段提示。 |
| BR-03 | 根据 ID 复制指定版本；来源不存在返回 404。无论来源是否启用，新记录均使用独立 ID、数据库生成的创建/更新时间、规范版本 `v1` 和 `enabled=false`，不调用激活逻辑；来源的内容、更新时间及启用状态均不因复制改变。 |
| BR-04 | 新记录复制 `scenario`、`task_type`、`template_type`、`content`、`messages`、`output_format`、`description`。按现有 payload 校验器处理类型与内容，重新解析 `variables`，chat 的 messages 含嵌套扩展数据也必须独立；不复制 `created_by` 或渲染日志。来源 payload 无法通过现有校验时为 400，不创建记录。 |
| BR-05 | 目标名称下只要存在任意版本，即返回 409，不能插入新记录或改变任何来源/已有版本。依赖数据库当前名称比较规则；在两个复制请求竞争同一 `v1` 时现有 `(name, version)` 唯一约束可阻止两个成功。另一个创建不同版本的并发事务可能与名称检查竞争：该数据库模型没有名称组唯一约束，本次不保证跨版本并发强一致。 |
| BR-06 | 成功返回 201 和完整新模板；界面跳转到新记录详情，显示未启用 v1。对新名称 `version=active` 渲染在启用之前返回 404；按 ID 预览和编辑可用，主动启用后 active 渲染可用。text 编辑保留 text 类型；chat 当前版本编辑只修改界面中第一条 system/user 的内容，保留其他消息及嵌套扩展字段。复制、预览、编辑不需要 AI API key。 |
| BR-07 | 重复提交相同名称返回 409，第一次成功结果仍保留；请求错误不得造成部分创建。原有按名称创建新版本的 API 与 UI 路径保持可用。 |

## UI 与接口状态

弹窗说明复制的是当前版本，结果为未启用的 v1；名称输入可获取焦点，错误就地提示；重复名称提示用户更换名称，其他网络或服务错误给出可见信息。弹窗内提供取消与复制，提交等待期间禁用操作，成功后按现有路由进入 `/admin/prompts/{new_id}`。中英文文案遵循现有语言切换。

| 状态码 | 条件 |
| --- | --- |
| 201 | 新模板创建成功。 |
| 400 | 来源数据不符合现有 chat/text 模板内容规则。 |
| 404 | 来源模板 ID 不存在。 |
| 409 | 目标名称已有任意版本，或新 `v1` 的唯一约束冲突。 |
| 422 | 请求体结构或名称字段不符合 BR-02。 |

## 验证边界

本地集成测试使用独立 SQLite 数据库和真实 FastAPI 请求，覆盖 chat/text、嵌套数据隔离、来源 active 不变、任意版本同名冲突、无效名称、重复请求、预览/编辑/启用；前端构建和真实浏览器交互另行记录。SQLite 测试不等于 MySQL 并发、生产安全、AI 模型质量或线上验收。

## 设计取舍与来源

方案 A 在详情页直接调用新端点创建未启用模板；方案 B 复用新建编辑器并让用户重新保存。选择 A：服务器复制完整结构并保留来源，避免编辑器只处理部分 message 字段导致静默丢失；保留现有编辑新版本路径。实现期间用浏览器复现了原 chat 编辑器保存时丢弃其他消息及扩展字段，因而将当前版本编辑的数据保留列入 BR-06；新版本路径保持原有语义。规格参考基线的 `backend/app/prompt/{models,schemas,service,router}.py`、`frontend/src/pages/{PromptDetailPage,PromptEditorPage}.tsx` 和 `README.md`。最终业务规则由用户或其指定产品负责人负责；该数据集的规则是本次受托设计，未记录虚构审批。
