# PM 记忆：指定版本复制为新模板

- 2026-10-30，用户授权选题、设计并为 QA Agent 创建真实实现和持久化记录。Codex 在该授权下手工模拟 PM；本文件是这次决策记录，不代表真实团队对话、外部访谈或额外审批。
- 来源基线 `10aeb958fe35c64b0b84388283d40e3ef64850cb`：`backend/app/prompt/models.py` 对 `(name, version)` 建唯一约束；`service.py` 的版本创建复用名称，`frontend/src/pages/PromptDetailPage.tsx` 原有操作进入 `/edit?newVersion=1`；`PromptEditorPage.tsx` 原本仅保存 chat。详见同目录 `PRD.md`。
- 选择复制当前 ID 指向的单个版本为独立名称、固定未启用 `v1`；理由是用户可安全预览并独立启用，同时不中断现有消费者。没有复制完整版本组、原作者、日志或自动启用。
- 名称首尾去空白，按规范化结果限制 1–100 Unicode 码点。无效输入采用 FastAPI 422，名称任意版本冲突采用 409，源不存在 404；符合现有服务对领域错误的 400 映射。
- 不改动“复制为新版本”；它与新模板复制回答不同需求。服务端复制整个合法 payload，而非从页面的 system/user 两个编辑框重建。为使 text 副本可在现有界面编辑，补充文本内容编辑路径。
- 实现时使用独立 SQLite 和浏览器复现：原 chat 编辑器保存后丢弃 assistant 消息和 system 消息嵌套元数据。为避免副本编辑后丢数据，补充“当前版本编辑保留未暴露字段及其他消息”的要求；新增版本仍沿用原有路径。这是本次实现期间的补充决策，不是先前审批。
- 名称组无独立唯一约束，检查后并发创建不同版本仍可能竞争；本次明确限制承诺而非声称已解决跨版本并发。数据库名称比较依赖其配置的 collation。
- 产品规则负责人：用户或用户指定的产品负责人；本次由 Codex 按授权作模拟决策。尚无额外真实审批、用户研究或生产验证记录。开放问题：未来是否要求跨版本并发下名称绝对独占及跨数据库一致的大小写规则；若需要应另行设计和迁移。
